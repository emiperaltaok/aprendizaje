Arquitectura de
Software vs Sistemas

Dos conceptos distintos que se complementan. Uno describe el interior del codigo. El otro describe como los sistemas se conectan entre si.

Las dos arquitecturas
No son lo mismo. No se reemplazan. Las dos existen en cualquier producto digital.
Vista interna
Arquitectura de Software
Como se organiza el codigo adentro de un sistema. Dominios, archivos, funciones, capas. Es la estructura interna que solo ve el desarrollador.
Como se dividen los dominios
Cuantos archivos tiene cada dominio

Como se comunican los componentes entre si
Patrones de diseno usados

Vista externa
Arquitectura de Sistemas
Como se conectan multiples sistemas entre si. Servidores, bases de datos, APIs, servicios externos, redes. Es la infraestructura que sostiene todo.
Donde corre el codigo (cloud, servidor)
Como se conectan los servicios externos
Quien maneja la base de datos
Como fluyen los datos entre sistemas
Seguridad, escalabilidad, disponibilidad
Pregunta que responde:
"Como se conecta todo con todo?"
La analogia del edificio
La forma mas clara de entender la diferencia.
Arquitectura de Software = Interior del edificio
Dominio: Pagos
Departamento de finanzas — tiene sus propias habitaciones y funciones
Dominio: Usuarios
Departamento de RRHH — maneja identidades y roles
Dominio: Turnos
Departamento de operaciones — coordina agenda y recursos
Archivos y funciones
Empleados con roles especificos dentro de cada departamento

Cuando pensas en cada una
Segun el momento del proyecto, te enfocas en una u otra.
Pensas en arquitectura de software cuando...
→
Diseñas como dividir el codigo en dominios
→
Decidis que hace cada archivo y que no
→
Le pides a Claude que construya una feature nueva
→
Auditás un repo con Understand Anything
→
Refactorizas codigo que crece demasiado
Pensas en arquitectura de sistemas cuando...
→
Elegis donde deployar (Vercel, AWS, Railway)
→
Conectas un servicio externo (API, DB, pago)
→
El sistema necesita escalar a mas clientes
→
Estudias el curso de AWS Solutions Architect
→
Planeas migrar de 7 servicios a AWS
El resumen en 3 conceptos
Arquitectura de software
El adentro
Dominios, archivos, funciones. Como esta organizado el codigo.
Arquitectura de sistemas
El afuera
Servicios, APIs, bases de datos. Como se conecta todo.
La relacion entre ambas
Complementarias
Todo producto digital necesita las dos. Una sin la otra no funciona.
